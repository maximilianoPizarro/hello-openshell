Developer Sandbox

Last checked: 2026-11-11 with OpenShell 0.1.8

Open the repo in a workspace. Startup installs the OpenShell 0.1.8 CLI. The sandbox project cannot host the gateway, so OpenShift Virtualization runs a Fedora VM in that project and the VM runs minikube. From the workspace terminal, the CLI creates the sandbox on that gateway.

Open in Developer Sandbox

1Open the workspace

Use the button, or in Developer Sandbox open Dev Spaces and create a workspace from this repository. devfile.yaml requests 512Mi / 200m and limits the tools container to 4Gi / 2 CPUs. Storage is ephemeral. On start it runs command 1 below. The other tasks stay manual (Terminal → Run Task…). Run them in the workspace shell: that shell can resolve minikube-vm.<project>.svc.cluster.local. A laptop cannot.

2Devfile commands

These are the exec commands, in the order you run them. 3. Start minikube VM already runs 4. Connect minikube gateway at the end. Run Connect on its own when the VM is already up. OpenShell version is optional: openshell --version (there is no openshell version subcommand). OpenShell terminal opens the live TUI after command 4: there is no web console in OpenShell 0.1.8.

1. bash scripts/install-openshell-cli.sh
2. bash scripts/sandbox-status.sh
3. bash scripts/sandbox-vm-up.sh
4. bash scripts/sandbox-vm-connect.sh
5. bash scripts/sandbox-vm-sandbox.sh
6. bash scripts/sandbox-ask.sh curl
7. bash scripts/sandbox-ask.sh python
8. bash scripts/sandbox-down.sh
9. bash scripts/sandbox-vm-inspect.sh
openshell gateway select minikube && openshell term

3Start the VM

scripts/sandbox-vm-up.sh prints oc whoami and the quota, then applies deploy/sandbox-minikube-vm.yaml. OpenShift Virtualization clones the fedora DataSource from openshift-virtualization-os-images. There is no custom image: Developer Sandbox shuts those down. runStrategy is Manual, and the script starts the guest with the start subresource. Inline cloud-init must name the user fedora and stays under 2048 bytes after the sandbox webhook adds its key. The text curls scripts/minikube-guest-boot.sh from this repository at the workspace commit.

PieceValue
Instanceu1.large, 2 vCPU / 8Gi, 30Gi disk
minikube1.39.0, Podman driver, containerd, --memory=3072 --cpus=2 --disk-size=10g --force
kubectl / Helm1.37.0 / 3.22.1
GatewayAgent Sandbox v1.0.10, OpenShell chart 0.1.8

The guest script runs as root. minikube 1.39 exits with DRV_AS_ROOT unless --force is set. It also stops if landlock is missing from /sys/kernel/security/lsm. The containers use that guest kernel. Developer Sandbox stops Linux VMs after one hour. Run the same task again after that. If the VM already exists, the script leaves the disk and cloud-init alone, so a new boot script needs 8. Clean first. The first successful boot installs the gateway. Connect waits up to 40 minutes for /var/lib/hello-openshell/ready. If that file never appears, the guest log is /var/log/cloud-init-output.log.

4Create the sandbox

Task 5. Create minikube sandbox runs scripts/sandbox-vm-sandbox.sh. It connects the CLI to https://127.0.0.1:8080 through an SSH tunnel (the server certificate includes localhost), selects the gateway minikube, and creates the sandbox on the cluster inside the VM:

openshell gateway select minikube
openshell sandbox create \
  --name model-check \
  --from registry.access.redhat.com/hi/python:3.12 \
  --policy deploy/hi-python.policy.yaml \
  -- /usr/bin/python3.12 -c 'print("ok")'

OpenShell 0.1.8 needs Landlock ABI v3 on the guest kernel. On 11 Nov 2026 this command printed ok and the phase was Completed. The gateway log then shows policy status=loaded and FinalizeMainProcessExit. The pod's containers are agent and two init containers. There is no supervisor container. If a later agent exits, openshell logs model-check and kubectl logs -n openshell default--model-check -c agent are the logs to read. Task 9. Inspect cluster prints them.

5Ask Granite

Task 6. Ask Granite does not use the VM. It runs a pod in this project and calls Granite, then Qwen, the same way LiteLLM does in rhdh-agent-sandbox: in-cluster DNS, port 8443, TLS verify off. No LiteMaaS key. HTTP has no header; HTTPS uses oc whoami -t for the oauth-proxy. If nothing answers, the predictors are not in CoreDNS; commands 4 and 5 are a separate path. Red Hat's walk-through is Get started with consuming GPU-hosted large language models.

6Ask with ask.py

Task 7. Ask with ask.py uses the same in-cluster pod and the Spanish prompt from examples/ask.py. The Dev Spaces tools container cannot resolve sandbox-shared-models; the pod can, when the predictors exist.

+OpenShell terminal

OpenShell 0.1.8 has no web console. The live dashboard is openshell term: three panels for gateways, providers, and sandboxes. Use Tab to move between panels and Enter for detail. Run task OpenShell terminal in the workspace terminal after command 4, or type:

openshell gateway select minikube
openshell term

If the task panel is not a TTY, paste the same commands into the workspace shell. Official notes: Manage Sandboxes.

7Clean

Task 8. Clean stops the SSH tunnel and deletes minikube-vm, rhel-vm, and objects labeled app.kubernetes.io/part-of=hello-openshell. It does not delete shared models or the workspace.

+RHEL terminal

Start RHEL terminal applies deploy/sandbox-rhel-vm.yaml. That guest is rhel-vm, cloned from the rhel9 DataSource with preference rhel.9. The login is cloud-user. The password is in ~/.config/hello-openshell/rhel.password, and the workspace key is the same one as the Fedora VM. This guest does not install minikube. dnf on the catalog image needs a subscription, so the gateway stays on minikube-vm.

ssh -i ~/.config/hello-openshell/minikube_ed25519 -o IdentitiesOnly=yes \
  cloud-user@rhel-vm.$(oc project -q).svc.cluster.local

From a laptop, oc port-forward svc/rhel-vm 2222:22 and SSH to 127.0.0.1 on port 2222. The console uses the same user and password file. Stop the Fedora VM first if the quota is full. Developer Sandbox still powers the guest off after one hour.

Gateway. A Developer Sandbox project cannot create CRDs, namespaces, or ClusterRoles, and agents.x-k8s.io is not served, so Helm chart 0.1.8 cannot install in the project itself. The chart runs inside the OpenShift Virtualization VM's minikube, where those limits do not apply. Do not pass OpenShift SCC values into that minikube. A cluster you administer is the OpenShift AI module.
