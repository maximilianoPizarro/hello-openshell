OpenShell en tu máquina

Un sandbox de Podman llama a Ollama llama3.2:1b por host.openshell.internal:11434. El gateway es OpenShell 0.1.8. El cliente es examples/ask.py.

Local

Podman, tope de 3 GiB, verificado en Windows 11.

Developer Sandbox

Tareas de Dev Spaces contra el Granite compartido.

OpenShift AI

Clúster de admin, una GPU, el token queda en el gateway.

0Antes de empezar

En esta máquina, Podman 6.1.4. La machine tiene que estar arriba y usar cgroup v2.

podman machine start
podman version
podman info --format '{{json .Host}}' | findstr cgroupVersion

1Levantar Ollama

Un contenedor, 3 GiB y 2 CPUs. Desde la raíz del repo.

podman compose -f deploy/compose.yaml up -d

Desde Git Bash en Windows el puerto publicado está en la IPv4 de la machine, no en 127.0.0.1.

OLLAMA_IP=$(MSYS_NO_PATHCONV=1 podman machine ssh "ip -4 -o addr show eth0" | awk '{print $4}' | cut -d/ -f1 | head -1)
until curl -fsS "http://${OLLAMA_IP}:11434/api/tags" >/dev/null; do sleep 2; done
podman exec ollama ollama pull llama3.2:1b
curl -sS "http://${OLLAMA_IP}:11434/v1/models" -H 'Authorization: Bearer fake'

2Instalar OpenShell dentro de la machine

podman machine ssh entra como root. Instalá 0.1.8 y fijá el socket rootful.

curl -LsSf https://raw.githubusercontent.com/NVIDIA/OpenShell/v0.1.8/install.sh | \
  OPENSHELL_VERSION=v0.1.8 sh

Bajo [openshell.drivers.podman] en ~/.config/openshell/gateway.toml:

socket_path = "/run/podman/podman.sock"
openshell-gateway config preflight --path ~/.config/openshell/gateway.toml
systemctl --user restart openshell-gateway
openshell gateway add https://127.0.0.1:17670 --local --name openshell
openshell gateway select openshell
openshell status

Resultado esperado: Connected, versión 0.1.8.

3Importar el perfil de Ollama

openshell profile lint -f deploy/ollama.profile.yaml
openshell profile import -f deploy/ollama.profile.yaml
openshell provider create --name ollama --type ollama
openshell provider get ollama

4Listar modelos desde un sandbox

openshell sandbox create \
  --name model-check \
  --from registry.access.redhat.com/hi/python:3.12 \
  --provider ollama \
  --policy deploy/hi-python.policy.yaml \
  -- /usr/bin/python3.12 -c 'import urllib.request; print(urllib.request.urlopen(urllib.request.Request("http://host.openshell.internal:11434/v1/models", headers={"Authorization":"Bearer fake"})).read().decode())'

El JSON tiene que incluir llama3.2:1b. El usuario de la imagen es el UID 65532 y su grupo primario es 0, así que la política fija usuario y grupo en 65532.

5Preguntar con ask.py

export MODEL_NAME=llama3.2:1b
openshell sandbox create \
  --name hello-agent \
  --from registry.access.redhat.com/hi/python:3.12 \
  --provider ollama \
  --policy deploy/hi-python.policy.yaml \
  --env OPENAI_BASE_URL=http://host.openshell.internal:11434/v1 \
  --env "MODEL_NAME=${MODEL_NAME}" \
  --env OPENAI_API_KEY=fake \
  -- /usr/bin/python3.12 -c "$(cat examples/ask.py)"

En esta máquina el modelo devolvió una frase y el log quedó en HTTP:POST ALLOWED.

6Bajar el laboratorio

openshell sandbox delete hello-agent model-check
openshell provider delete ollama
openshell profile delete ollama
podman compose -f deploy/compose.yaml down -v
