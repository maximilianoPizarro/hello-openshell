OpenShell en tu máquina

Verificado con OpenShell 0.1.8

Ejecutá un agente de IA dentro de un sandbox aislado que solo puede hablar con el modelo que vos autorizás. En esta guía levantás Ollama con Podman, conectás OpenShell y verificás que el sandbox llega al modelo a través de una política de red. Tiempo estimado: 15 minutos. Requisitos: Podman y 4 GiB de RAM libres.

Local

Corré todo en tu equipo con Podman. Verificado en Linux, macOS y Windows.

Developer Sandbox

Usá el CLI desde Dev Spaces. El gateway corre en minikube, dentro de una VM de OpenShift Virtualization.

OpenShift AI

Referencia para administradores: modelo en un clúster con una GPU; el token nunca sale del gateway.

Cloud Shell

Prueba parcial: el gateway corre en minikube, pero Cloud Shell no puede ejecutar el sandbox (limitación del kernel).

Cómo funciona

Un sandbox de Podman llama a Ollama llama3.2:1b por host.openshell.internal:11434. El gateway es OpenShell 0.1.8. El cliente es examples/ask.py.

Glosario

Sandbox
Contenedor aislado donde corre tu código, sin red propia.
Gateway
Servicio que crea y administra los sandboxes.
Supervisor
Proceso que decide qué conexiones salen del sandbox.
Profile / Provider
Perfil de políticas y registro del backend de inferencia (Ollama).

1Quickstart

Qué hace: clona el repo, levanta Ollama, instala el gateway, hace una pregunta y limpia el entorno.

git clone https://github.com/maximilianoPizarro/hello-openshell
cd hello-openshell
make up
make gateway
make ask
make down

make up levanta Ollama y baja el modelo. make gateway instala OpenShell 0.1.8. make ask corre examples/ask.py en el sandbox de Python endurecido. Deberías ver una frase en español sobre qué es un sandbox.

Resultado esperado: Status Connected y Version 0.1.8 después de make gateway; una respuesta corta en español después de make ask.

Si falla: mirá Cuando algo falla.

2Plataformas

Qué hace: muestra cómo el host, la VM de Podman y el sandbox llegan a Ollama.

PlataformaPodmanURL del host para OllamaGateway
LinuxNativohttp://127.0.0.1:11434En el host
macOSpodman machinePuerto publicado en localhostDentro de la VM de Podman
Windowspodman machine en WSL2localhost con mirrored, o IPv4 de la VM con NATDentro de la VM de Podman

scripts/ollama-url.sh imprime la URL del host. El sandbox siempre usa host.openshell.internal:11434. En Windows, networkingMode=mirrored en %USERPROFILE%\.wslconfig hace que localhost funcione desde el host. Necesitás la VM de Podman iniciada y cgroup v2 activo. Dentro de podman machine ssh sos usuario root.

Si falla: filas de Plataforma o Red en Cuando algo falla.

3Importar el perfil de Ollama

Qué hace: registra qué hosts y puertos puede usar el sandbox, y crea el provider de Ollama.

openshell profile lint -f deploy/ollama.profile.yaml
openshell profile import -f deploy/ollama.profile.yaml
openshell provider create --name ollama --type ollama
openshell provider get ollama

Resultado esperado: Profile ollama imported y provider ollama listado.

Si falla: filas de Política en Cuando algo falla.

4Listar modelos desde un sandbox

Qué hace: crea un sandbox breve y lista los modelos por el host permitido.

openshell sandbox create \
  --name model-check \
  --from registry.access.redhat.com/hi/python:3.12 \
  --provider ollama \
  --policy deploy/hi-python.policy.yaml \
  -- /usr/bin/python3.12 -c 'import urllib.request; print(urllib.request.urlopen(urllib.request.Request("http://host.openshell.internal:11434/v1/models", headers={"Authorization":"Bearer fake"})).read().decode())'

El usuario de la imagen es el UID 65532 y su grupo primario es 0, así que la política fija usuario y grupo en 65532.

Resultado esperado: JSON que incluye llama3.2:1b.

Si falla: filas de Modelo, Imagen o Política en Cuando algo falla.

5Preguntar con ask.py

Qué hace: corre examples/ask.py en un sandbox para que la política permita el POST y el supervisor llegue a Ollama.

Importante. fake es un valor de relleno: el cliente exige una clave, pero Ollama no la valida. El proceso ve ese valor. Para una credencial real, creá un provider y adjuntálo con --provider en lugar de --env.

export MODEL_NAME=llama3.2:1b
openshell sandbox create \
  --name hello-agent \
  --from registry.access.redhat.com/hi/python:3.12 \
  --provider ollama \
  --policy deploy/hi-python.policy.yaml \
  --env OPENAI_BASE_URL=http://host.openshell.internal:11434/v1 \
  --env "MODEL_NAME=${MODEL_NAME}" \
  --env OPENAI_API_KEY=fake \
  -- /usr/bin/python3.12 -c "$(cat examples/ask.py)"

Resultado esperado: una frase en español que explica qué es un sandbox y por qué un agente debería correr dentro de uno.

Si falla: filas de Gateway, Imagen o Política en Cuando algo falla.

6Limpiar el entorno

Qué hace: apaga el laboratorio y, con -v, también borra los modelos descargados.

make down

O borrá los sandboxes y después corré podman compose -f deploy/compose.yaml down -v. Eso también borra el volumen deploy_ollama, con los modelos descargados.

Resultado esperado: sin contenedor Ollama en ejecución y sin sandboxes activos de este laboratorio.

Cuando algo falla

CategoríaQué vesDónde mirar
Plataformapodman no puede conectarpodman machine start en macOS/Windows. En Linux, iniciá el socket de Podman.
MemoriaEl contenedor de Ollama se matapodman stats ollama. Subí mem_limit en deploy/compose.yaml a 4g. Quedate en llama3.2:1b si la RAM es justa.
Modelo/v1/models no tiene llama3.2:1bpodman exec ollama ollama pull llama3.2:1b todavía corre. podman logs ollama.
Red (Windows NAT)curl a 127.0.0.1:11434 desde Windows da connection refusedUsá make ollama-url, o pasá WSL a networkingMode=mirrored.
GatewayEl gateway no crea contenedoressocket_path tiene que ser el demonio que lista ollama.
ImagenEl sandbox sale nombrando Landlock o seccompEl kernel rechazó el filtro. OpenShell 0.1.8 necesita ese control.
Políticano matching policy nombra un binarioEn la imagen endurecida el intérprete es /usr/bin/python3.12. Actualizá el perfil y conservá resource_version.
Políticaconfigure an explicit workload groupEl usuario de la imagen 65532 tiene grupo primario 0. Pasá --policy deploy/hi-python.policy.yaml.
Políticaresolves to always-blocked addressLa URL del sandbox usó loopback. Usá host.openshell.internal.
