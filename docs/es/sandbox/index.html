Developer Sandbox

Última verificación: 2026-11-11 con OpenShell 0.1.8

Abrí el repo en un workspace. Al arrancar se instala el CLI de OpenShell 0.1.8. El proyecto del sandbox no puede alojar el gateway, así que OpenShift Virtualization corre una VM Fedora en ese proyecto y esa VM corre minikube. Desde la terminal del workspace, el CLI crea el sandbox en ese gateway.

Abrir en Developer Sandbox

1Abrir el workspace

Usá el botón, o en el Developer Sandbox abrí Dev Spaces y creá un workspace con este repo. devfile.yaml pide 512Mi / 200m y limita el contenedor a 4Gi / 2 CPUs. El storage es efímero. Al arrancar corre el comando 1 de abajo. El resto de las tareas se eligen a mano (Terminal → Run Task…). Corrélas en la shell del workspace: esa shell resuelve minikube-vm.<proyecto>.svc.cluster.local. Una laptop no.

2Comandos del devfile

Estos son los comandos exec, en el orden de ejecución. 3. Start minikube VM ya corre 4. Connect minikube gateway al final. Connect solo hace falta otra vez si la VM ya estaba arriba. OpenShell version es opcional: openshell --version (no existe openshell version). OpenShell terminal abre el TUI en vivo después del comando 4: OpenShell 0.1.8 no tiene consola web. Los nombres de las tareas quedan en inglés porque son el texto del IDE.

1. bash scripts/install-openshell-cli.sh
2. bash scripts/sandbox-status.sh
3. bash scripts/sandbox-vm-up.sh
4. bash scripts/sandbox-vm-connect.sh
5. bash scripts/sandbox-vm-sandbox.sh
6. bash scripts/sandbox-ask.sh curl
7. bash scripts/sandbox-ask.sh python
8. bash scripts/sandbox-down.sh
9. bash scripts/sandbox-vm-inspect.sh
openshell gateway select minikube && openshell term

3Arrancar la VM

scripts/sandbox-vm-up.sh muestra oc whoami y la cuota, y aplica deploy/sandbox-minikube-vm.yaml. OpenShift Virtualization clona el DataSource fedora de openshift-virtualization-os-images. No hay imagen propia: Developer Sandbox apaga esas. runStrategy es Manual, y el script arranca el guest con el subrecurso start. El cloud-init inline tiene que nombrar al usuario fedora y queda bajo 2048 bytes después de que el webhook del sandbox agrega su clave. Ese texto baja scripts/minikube-guest-boot.sh de este repositorio, en el commit del workspace.

PiezaValor
Instanciau1.large, 2 vCPU / 8Gi, disco de 30Gi

El script del guest corre como root. minikube 1.39 sale con DRV_AS_ROOT si falta --force. También se detiene si landlock no está en /sys/kernel/security/lsm. Los contenedores usan ese kernel. Developer Sandbox apaga las VMs Linux a la hora. Volvé a correr la misma tarea después. Si la VM ya existe, el script deja el disco y el cloud-init como están, así que un script de arranque nuevo pide 8. Clean antes. El primer arranque que termina instala el gateway. Connect espera hasta 40 minutos a /var/lib/hello-openshell/ready. Si ese archivo no aparece, el log del guest es /var/log/cloud-init-output.log.

4Crear el sandbox

La tarea 5. Create minikube sandbox corre scripts/sandbox-vm-sandbox.sh. Conecta el CLI a https://127.0.0.1:8080 por un túnel SSH (el certificado del servidor incluye localhost), selecciona el gateway minikube y crea el sandbox en el clúster de la VM:

openshell gateway select minikube
openshell sandbox create \
  --name model-check \
  --from registry.access.redhat.com/hi/python:3.12 \
  --policy deploy/hi-python.policy.yaml \
  -- /usr/bin/python3.12 -c 'print("ok")'

OpenShell 0.1.8 necesita Landlock ABI v3 en el kernel del guest. El 11 Nov 2026 este comando imprimió ok y la fase quedó Completed. El log del gateway muestra policy status=loaded y FinalizeMainProcessExit. Los contenedores del pod son agent y dos init. No hay un contenedor supervisor. Si un agente posterior sale, los logs son openshell logs model-check y kubectl logs -n openshell default--model-check -c agent. La tarea 9. Inspect cluster los imprime.

5Ask Granite

La tarea 6. Ask Granite no usa la VM. Llama al predictor compartido https://isvc-granite-31-8b-fp8-predictor.sandbox-shared-models.svc.cluster.local:8443/v1 con el modelo isvc-granite-31-8b-fp8. El token es oc whoami -t y no se escribe en git. TLS usa la CA de servicio. No hace falta exportar una URL. Pisá con SANDBOX_MODEL_BASE solo si querés otro endpoint. Si /v1/models falla, el script igual manda el chat con ese model id. La guía de Red Hat es consumir los modelos con GPU del sandbox.

6Ask with ask.py

La tarea 7. Ask with ask.py usa la misma URL de Granite por defecto y después corre python3 examples/ask.py con OPENAI_BASE_URL, MODEL_NAME, RHOAI_API_TOKEN y SSL_CERT_FILE. El prompt del script es una frase en español.

+OpenShell terminal

OpenShell 0.1.8 no tiene consola web. El tablero en vivo es openshell term: tres paneles para gateways, providers y sandboxes. Con Tab cambiás de panel y con Enter abrís el detalle. Corré la tarea OpenShell terminal en la terminal del workspace después del comando 4, o escribí:

openshell gateway select minikube
openshell term

Si el panel de la tarea no es un TTY, pegá los mismos comandos en la shell del workspace. Notas oficiales: Manage Sandboxes.

7Clean

La tarea 8. Clean corta el túnel SSH y borra minikube-vm, rhel-vm y los objetos con la etiqueta app.kubernetes.io/part-of=hello-openshell. No borra modelos compartidos ni el workspace.

+Terminal RHEL

Start RHEL terminal aplica deploy/sandbox-rhel-vm.yaml. Ese guest es rhel-vm, clonado del DataSource rhel9 con la preferencia rhel.9. El usuario es cloud-user. La contraseña queda en ~/.config/hello-openshell/rhel.password, y la clave del workspace es la misma que la de la VM Fedora. Este guest no instala minikube. dnf en la imagen del catálogo pide suscripción, así que el gateway sigue en minikube-vm.

ssh -i ~/.config/hello-openshell/minikube_ed25519 -o IdentitiesOnly=yes \
  cloud-user@rhel-vm.$(oc project -q).svc.cluster.local

Desde una laptop, oc port-forward svc/rhel-vm 2222:22 y SSH a 127.0.0.1 en el puerto 2222. La consola usa el mismo usuario y el mismo archivo de contraseña. Apagá la VM Fedora primero si la cuota está llena. Developer Sandbox igual apaga el guest a la hora.

Gateway. Un proyecto de Developer Sandbox no puede crear CRDs, namespaces ni ClusterRoles, y agents.x-k8s.io no está servida, así que el chart 0.1.8 no se puede instalar en el proyecto. El chart corre dentro del minikube de la VM de OpenShift Virtualization, donde esos límites no aplican. No pases valores de SCC de OpenShift a ese minikube.
