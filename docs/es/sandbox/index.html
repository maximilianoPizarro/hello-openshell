Developer Sandbox

Última verificación: 2026-11-12 con OpenShell 0.1.8

Abrí el repo en un workspace. Al arrancar se instala el CLI de OpenShell 0.1.8. El proyecto del sandbox no puede alojar el gateway, así que OpenShift Virtualization corre una VM Fedora en ese proyecto y esa VM corre minikube. Desde la terminal del workspace, el CLI crea el sandbox en ese gateway.

Abrir en Developer Sandbox

1Abrir el workspace

Usá el botón, o en el Developer Sandbox abrí Dev Spaces y creá un workspace con este repo. devfile.yaml pide 512Mi / 200m y limita el contenedor a 4Gi / 2 CPUs. El storage es efímero. Al arrancar corre el comando 1 de abajo. El resto de las tareas se eligen a mano (Terminal → Run Task…). Corrélas en la shell del workspace: esa shell resuelve minikube-vm.<proyecto>.svc.cluster.local. Una laptop no.

2Comandos del devfile

Estos son los comandos exec, en el orden de ejecución. 3. Start minikube VM ya corre 4. Connect minikube gateway al final. Connect solo hace falta otra vez si la VM ya estaba arriba. OpenShell version es opcional: openshell --version (no existe openshell version). 10. OpenShell UI abre el TUI en el browser de Dev Spaces después del comando 4. Los nombres de las tareas quedan en inglés porque son el texto del IDE.

3Arrancar la VM

scripts/sandbox-vm-up.sh muestra oc whoami y la cuota, y aplica deploy/sandbox-minikube-vm.yaml. OpenShift Virtualization clona el DataSource fedora de openshift-virtualization-os-images. No hay imagen propia: Developer Sandbox apaga esas. runStrategy es Manual, y el script arranca el guest con el subrecurso start. El cloud-init inline tiene que nombrar al usuario fedora y queda bajo 2048 bytes después de que el webhook del sandbox agrega su clave. Ese texto baja scripts/minikube-guest-boot.sh de este repositorio, en el commit del workspace.

El script del guest corre como root. minikube 1.39 sale con DRV_AS_ROOT si falta --force. También se detiene si landlock no está en /sys/kernel/security/lsm. Los contenedores usan ese kernel. Developer Sandbox apaga las VMs Linux a la hora. Volvé a correr la misma tarea después. Si la VM ya existe, el script deja el disco y el cloud-init como están, así que un script de arranque nuevo pide 8. Clean antes. El primer arranque que termina instala el gateway. Connect espera hasta 40 minutos a /var/lib/hello-openshell/ready. Si ese archivo no aparece, el log del guest es /var/log/cloud-init-output.log.

4Crear el sandbox

La tarea 5. Create minikube sandbox corre scripts/sandbox-vm-sandbox.sh. Conecta el CLI a https://127.0.0.1:8080 por un túnel SSH (el certificado del servidor incluye localhost), selecciona el gateway minikube y crea el sandbox en el clúster de la VM:

openshell gateway select minikube
openshell sandbox create \
  --name model-check \
  --from registry.access.redhat.com/hi/python:3.12 \
  --policy deploy/hi-python.policy.yaml \
  -- /usr/bin/python3.12 -c 'print("ok")'

OpenShell 0.1.8 necesita Landlock ABI v3 en el kernel del guest. El 11 Nov 2026 este comando imprimió ok y la fase quedó Completed. El log del gateway muestra policy status=loaded y FinalizeMainProcessExit. Los contenedores del pod son agent y dos init. No hay un contenedor supervisor. Si un agente posterior sale, los logs son openshell logs model-check y kubectl logs -n openshell default--model-check -c agent. La tarea 9. Inspect cluster los imprime.

5Ask from the sandbox

La tarea 6. Ask from the sandbox es el mismo camino que make ask en tu máquina. Necesita los comandos 3 y 4. Crea el sandbox hello-ask desde registry.access.redhat.com/hi/python:3.12, importa deploy/ollama.profile.yaml y corre examples/ask.py adentro. El sandbox no tiene red propia. El supervisor llama a host.openshell.internal:11434 en el guest Fedora, que hace de proxy a Ollama CPU llama3.2:1b en este proyecto (deploy/sandbox-ollama.yaml, tope 4Gi, cuota de GPU 0). El comando 6 lista /v1/models y pregunta una frase en inglés. Si rhel-vm está Running, parala antes del comando 3.

6Ask with ask.py

La tarea 7. Ask with ask.py crea hello-agent igual, con el prompt en español de examples/ask.py. Los dos sandboxes usan deploy/hi-python.policy.yaml. El comando 5 sigue siendo la prueba de humo (print("ok") en model-check); 6 y 7 son el agente que habla con el modelo.

10OpenShell UI

OpenShell 0.1.8 no tiene consola web. La tarea 10. OpenShell UI corre el TUI oficial (openshell term) dentro de ttyd en el puerto 7681. El contenedor de tools declara un endpoint público openshell-ui, así Dev Spaces crea una Route y el panel PORTS lo abre en el Simple Browser. Reiniciá el workspace una vez cuando ese endpoint esté en devfile.yaml. Dejá la tarea corriendo. Tab y Enter siguen moviendo gateways, providers y sandboxes. Notas oficiales: Manage Sandboxes.

7Clean

La tarea 8. Clean corta el túnel SSH y borra minikube-vm, rhel-vm, Ollama y los objetos con la etiqueta app.kubernetes.io/part-of=hello-openshell. No borra modelos compartidos ni el workspace.

+Terminal RHEL

Start RHEL terminal aplica deploy/sandbox-rhel-vm.yaml. Ese guest es rhel-vm, clonado del DataSource rhel9 con la preferencia rhel.9. El usuario es cloud-user. La contraseña queda en ~/.config/hello-openshell/rhel.password, y la clave del workspace es la misma que la de la VM Fedora. Este guest instala MicroShift en lugar de minikube. La imagen del catálogo no tiene suscripción, así que el script de arranque usa el mirror público de MicroShift 4.22 y AlmaLinux 9 para los paquetes base.

Connect MicroShift corre scripts/sandbox-rhel-connect.sh. Antes, guardá un pull secret de Red Hat en ~/.config/hello-openshell/openshift-pull-secret. El script copia ese archivo, corre scripts/microshift-guest-boot.sh por SSH y registra el gateway:

openshell gateway add https://127.0.0.1:8080 --local --name microshift
openshell gateway select microshift

El 12 Nov 2026 el guest era RHEL 9.9 con Landlock ABI 6. El nodo pasó a Ready, el CLI se conectó a OpenShell 0.1.8, y `model-check` imprimió `ok` después de atar un volumen hostPath de 2Gi al claim del workspace. En este disco no hay un provisioner. El disco raíz no tiene un volume group LVM, así que el volumen del gateway es hostPath. El hostname rhel-vm coincide con el Service; el script lo fija en /etc/hosts para que el API server llegue al kubelet. Desde una laptop, oc port-forward svc/rhel-vm 2222:22 y SSH a 127.0.0.1 en el puerto 2222. Apagá la VM Fedora primero si la cuota está llena. Developer Sandbox igual apaga el guest a la hora.

Gateway. Un proyecto de Developer Sandbox no puede crear CRDs, namespaces ni ClusterRoles, y agents.x-k8s.io no está servida, así que el chart 0.1.8 no se puede instalar en el proyecto. El chart corre dentro del minikube de la VM de OpenShift Virtualization, donde esos límites no aplican. No pases valores de SCC de OpenShift a ese minikube. El módulo para un clúster que administres es OpenShift AI.
